# Грузчики — сервис заказов на перевозку

Веб-платформа для грузчиков: заказчики публикуют заказы (переезды, погрузка/разгрузка),
грузчики видят ленту заказов на сегодня, берут их, пополняют баланс и получают
телефон заказчика после оплаты. Администратор подтверждает оплаты через админ-панель
или Telegram-бота.

## Стек

| Слой    | Технологии |
|---------|------------|
| Бэкенд  | FastAPI, SQLAlchemy 2.0, JWT (PyJWT), WebSocket, SQLite/PostgreSQL |
| Фронтенд | React 18 + TypeScript, Vite 5, Tailwind CSS 3, React Router 6 |
| Интеграции | Telegram Bot API (уведомления + подтверждение оплат с кнопками) |

## Установка и запуск

### 1. Бэкенд (FastAPI, порт 8000)

```bash
cd backend

# Виртуальное окружение
python -m venv venv
venv\Scripts\activate            # Windows
source venv/bin/activate         # Linux/macOS

# Зависимости
pip install -r requirements.txt

# Конфигурация
copy .env.example .env           # Windows
cp .env.example .env             # Linux/macOS
# → в .env замените JWT_SECRET и при необходимости реквизиты/телеграм-настройки

# Запуск (создаст БД и админа автоматически)
python run.py
```

Проверка: http://localhost:8000/health → `{"status":"ok"}`.
Документация API (Swagger): http://localhost:8000/docs

### 2. Фронтенд (React + Vite, порт 5173)

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173 — Vite проксирует `/api`, `/ws` и `/uploads`
на бэкенд, отдельная настройка CORS не нужна.

Продакшен-сборка: `npm run build` (результат в `frontend/dist`).

## Telegram-бот администратора

Бот присылает уведомления о новых заявках на пополнение баланса
(с кнопками «Подтвердить / Отклонить»), о взятии заказов и о новых
заказах с публичной формы сайта («🆕 Новый заказ с сайта!»).

Настройка в `backend/.env`:

```
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...   # токен от @BotFather
TELEGRAM_ADMIN_CHAT_ID=123456789       # ваш chat_id (узнать: @userinfobot)
```

Напишите боту `/start` — он подтвердит, что уведомления будут доставляться.
Если токен пустой — бот выключен, сайт работает без интеграции.

Как работает:

1. Новое пополнение → админу приходит сообщение с кнопками.
2. Нажатие кнопки бот обрабатывает в фоне (long polling) и сразу
   подтверждает/отклоняет оплату — баланс грузчика меняется.
3. Решения принимает только чат из `TELEGRAM_ADMIN_CHAT_ID`.

Запуск бота: автоматически вместе с бэкендом (фоновый поток), либо
отдельно командой `python -m app.services.bot`.

## Заказы с площадок (агрегатор)

Страница `/sources` («Площадки») помогает грузчикам находить заказы вне платформы:

- **Живая лента** — настоящие вакансии/заказы через открытые API:
  «Работа России» (trudvsem.ru) и hh.ru. Ответы кэшируются на 10 минут,
  недоступный источник не роняет страницу (лента продолжает работать).
  Отклик на заказ происходит на самой площадке.
- **Справочник 20+ площадок** — Avito, YouDo, Profi.ru, Юла, SuperJob,
  Работа.ру, ГородРабот, Зарплата.ру, Trud.com, VK Работа, Яндекс Услуги,
  Нон Стоп Грузчик, Грузчики24, ВсеГрузчики, Грузчики-Сервис, Грузовичкоф,
  Газелькин, ATI.SU, Переезд.ру и Telegram-чаты.

> Парсинг Avito, YouDo, Profi.ru и «Юлы» запрещён их правилами и заблокирован
> капчей, поэтому для них даются прямые ссылки, а не сбор данных.

Список площадок и живые источники редактируются в одном файле:
`backend/app/services/order_sources.py`. Для подключения новой площадки с
открытым API достаточно добавить функцию-загрузчик и имя в `_FEED_SOURCES`.

Примечание: API hh.ru может быть недоступен из-за пределов РФ (гео-блокировка) —
в этом случае источник просто показывает «нет данных», остальная лента работает.

## Форма размещения заказа для заказчиков

Публичная страница `/place-order` («Разместить заказ») работает без
регистрации и авторизации: заказчик указывает город, адрес, имя и телефон,
цену, категорию, срочность и описание.

- **Эндпоинт**: `POST /orders/public` — создаёт заказ со `status="active"`
  и `source="form"`, имя заказчика сохраняется в `customer_name`.
- **Уведомления**: заказ сразу появляется в ленте у грузчиков выбранного
  региона (WebSocket-рассылка), админу приходит уведомление в Telegram.
- **Миграции**: колонки `orders.customer_name` и `orders.source` добавляются
  в существующие базы автоматически при старте сервера
  (`ALTER TABLE ADD COLUMN` в `backend/app/seed.py`) — обновление не требует
  ручных действий.
- **Telegram для связи**: в шапке сайта есть ссылка «Написать админу»
  (открывает Telegram-чат администратора, имя бота из `TELEGRAM_BOT_USERNAME`).

## Основные возможности

**Заказчик**
- страница «Разместить заказ» (`/place-order`): форма без авторизации;
- заказ сразу попадает в общую ленту региона (WebSocket) и админу в Telegram;
- ссылка «Написать админу» в шапке для вопросов.

**Грузчик**
- лента заказов на сегодня в реальном времени (WebSocket, обновление при новых заказах);
- детальная карточка заказа: адрес, цена, телефон заказчика (виден при балансе ≥ порога);
- взятие заказа — списывается комиссия, админ получает уведомление;
- пополнение баланса: перевод по банковским реквизитам + загрузка чека;
- профиль: статистика (сегодня/неделя/месяц), история заказов и пополнений;
- «Заказы с площадок»: живая лента вакансий (Работа России, hh.ru) + справочник 20+ сервисов для поиска заказов.

**Администратор** (`/admin`)
- дашборд: пользователи, заказы, доход от комиссий, неподтверждённые оплаты;
- заказы: создание вручную, завершение, удаление;
- грузчики: балансы, блокировка/разблокировка;
- пополнения: просмотр квитанций, подтверждение/отклонение;
- регионы (города), настройка комиссии, журнал действий;
- Telegram-бот для подтверждения оплат с телефона.

## Проверка API

Бэкенд покрыт набором из 38 e2e-проверок (регистрация, вход, лента заказов,
взятие заказа, списание комиссии, пополнение с загрузкой чека, подтверждение
оплаты, админ-эндпоинты, блокировка) — все проходят на свежей базе.
Повторно прогнать проверки можно любым HTTP-клиентом по Swagger
